# trellis-learning-content

Generated by `build-logic/scripts/dev/new-module.sh --name course --aggregate Course --plural courses`
from `trellis-notice`. What is here is a **working skeleton**, not the real use case: a Course with a name, a
description and a DRAFT -> ACTIVE -> ARCHIVED lifecycle, so the module compiles, boots and answers HTTP before
you have written a single business rule. Replace it; do not grow it by adding fields you do not need.

Tutorial (Vietnamese): [`docs/guide/new-module.md`](../docs/guide/new-module.md).

## Layout (decision T17: fixed sub-packages, even when they hold one file)

This module groups 4 features (decision T26): `course`, `lesson`, `authoring`, `publishing`. The tree above shows `course`, which the generator filled in; the others are `domain/` and `application/` packages to fill in: `lesson`, `authoring`, `publishing`.
`api/`, `infrastructure/` and `web/` are **not** split per feature: they are the module's one
published surface, one set of adapters and one set of entry points.

A sub-package exists once it holds a class. Three of them hold none yet: `api/event` (the module publishes no event),
`infrastructure/messaging` (no consumer, no read model) and `infrastructure/client` (no external service). Keep
them: a growing module then never needs re-sorting. `trellis-notice` is the live example of all three.

## API

| REST | Notes |
| --- | --- |
| `POST /api/courses` | 201, `Location`, `ETag`; needs `course:manage` |
| `GET /api/courses?first=&after=&status=&query=` | `{items, nextCursor, hasNext}` |
| `GET /api/courses/{code}` | `ETag` |
| `PUT /api/courses/{code}` | `If-Match` required; stale = 412 `COURSE_VERSION_MISMATCH` |
| `POST /api/courses/{code}/activate` | DRAFT or ARCHIVED -> ACTIVE |
| `POST /api/courses/{code}/archive` | soft delete: the platform keeps the row |

The catalog uses the REST list and detail endpoints.

Both APIs are part of the committed contracts, so after any change to an endpoint or the schema run
`./gradlew :trellis-app:exportApiContracts` and commit `contracts/`.

## The five places to edit for the real use case

1. `domain/model/Course.java` - the fields and the transitions. Everything decidable from the aggregate alone.
2. `application/validation/CourseValidator.java` - the rules; they report violations, so the caller gets all of
   them at once.
3. `api/security/CoursePermissions.java` plus the role mapping in
   `src/main/resources/db/changelog/learning-content/002-course-roles.sql`, and the realm roles in
   `build-logic/docker/keycloak/trellis-realm.json` for local runs. A permission nobody holds is a 403 on every call.
4. `src/main/resources/db/changelog/course/001-course.sql` - while nothing has been applied anywhere you may
   still edit this changeset; afterwards add `002-...` instead.
5. `web/rest/CourseController.java` - the shape clients see.
   Controllers stay thin: no rules, no authorization, no transactions (ArchUnit enforces it).

Then: an event (`api/event` + outbox, write the JSON Schema first), a read model
(`infrastructure/messaging`), an external client (`infrastructure/client`) - each has a live example in
`trellis-notice`.

Tests (decision T5): none here. Only the platform and `trellis-notice`'s reference flow are tested; do not add
feature tests unless the owner asks.
